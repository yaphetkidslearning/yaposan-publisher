# Good First Issue Seed List

Maintainers can turn these into GitHub issues before or during the public launch. Each issue should be narrowed to a specific file or screen before labeling it `good first issue`.

1. Improve one Help Center article for clarity and add a regression assertion.
2. Add missing accessible labels to one dialog or toolbar.
3. Fix one keyboard-focus visibility problem and include before/after screenshots.
4. Add a focused browser compatibility test for a public route.
5. Improve one Project Library empty state without changing data behavior.
6. Add one glossary entry and link it from the relevant help article.
7. Add one FAQ question based on a real user workflow.
8. Improve alt text for a public marketing image.
9. Add documentation for one commonly used keyboard shortcut group.
10. Add a small set of tests for a previously uncovered utility function.
11. Improve one template preview's responsive behavior.
12. Add a sanitized development troubleshooting note for a common setup failure.
13. Improve one contributor-facing error message with an actionable next step.
14. Add a small localization-readiness cleanup by extracting hard-coded user-facing strings in one component.
15. Document one server endpoint's local-development behavior without exposing production secrets.
16. Add a regression test ensuring public pages do not accidentally require authentication.
17. Improve one loading or empty state for screen-reader users.
18. Add one narrowly scoped performance measurement around template search or filtering.
19. Improve a code comment around an unusual editor behavior and add a test that explains the invariant.
20. Add one example screenshot/GIF to contributor documentation using redistributable project assets.

## Good first issue quality bar

A beginner issue should include:

- exact files or feature area
- a small expected outcome
- acceptance criteria
- how to run the relevant test
- whether a screenshot is expected
- a maintainer contact path through the issue discussion

Do not label broad requests such as "improve the editor" or "add AI" as `good first issue`.
