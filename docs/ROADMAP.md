# Yaposan Community Roadmap

This roadmap is a public contribution guide, not a promise of dates or a substitute for GitHub issues.

## Now: make contribution easy and safe

Priorities:

- fast local setup and dependable web development
- accessibility and keyboard navigation
- editor reliability and regression coverage
- clear Help/FAQ/troubleshooting content
- performance on large projects and template libraries
- safe open-source security boundaries
- documentation that lets a first-time contributor succeed without reading obsolete development files

## Next: strengthen the creative ecosystem

Community-friendly areas include:

- new and improved publication templates
- localization and translation readiness
- import/export compatibility
- browser compatibility
- reusable design components
- plugin/developer documentation
- local-first and bring-your-own-provider AI workflows

## Later: scale the platform responsibly

Longer-term themes include:

- collaboration quality and conflict handling
- public API and integration quality
- desktop/offline/mobile companion maturity
- creator marketplace tooling
- production observability and reliability
- enterprise governance features that do not weaken the open-source core

## How roadmap work becomes real

The issue tracker is the source of truth for work that is ready to be picked up. A roadmap item should become a focused issue with:

- a clear problem statement
- acceptance criteria
- expected test coverage
- screenshots or reproduction steps when relevant
- a size small enough for one pull request when practical

Use `good first issue` for small, well-bounded tasks and `help wanted` for work where maintainers are actively looking for community help.
